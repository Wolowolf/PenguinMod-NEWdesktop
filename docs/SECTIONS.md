# Editor sections — what each change does

Not read by default: Grep for the section you need (e.g. `- 21:`). The short list is in `/CHANGES.md`. Until Session 29 these were `patches/stage-layout.js`; now each is one commit on branch `desktop` of the forks: `git revert <commit>` reverses one, `git -C <checkout> show --stat <commit>` lists its files.

- 1–7: the editor stage always fits a 480 px wide 4:3 box. The small/large buttons are removed. A drag handle sits on the stage column's left edge (240–1200 px, double-click resets, saved in `localStorage` `pmdesktop:stageBoxWidth`). The column hugs the stage, with a minimum width of 242 px. (Sessions 2–3)
- 8: the sprite panel is one wrapping row: eye toggle, name, x, y, ⇪ size, ⟳ direction. (Session 4)
- 9: automatic restore points are off by default. (Session 3)
- 10: no rounded corners, CSS only (block shapes are SVG and stay rounded). (Session 4)
- 11: the category menu shows colour boxes with the name only. The menu is 4.5rem wide; boxes are one line, the selected box two lines, with white outlined text; a name that does not fit is cut off without "..." and gets a small dot under its first letter. It also wraps `Toolbox.Category.createDom`, `Toolbox.Category.setSelected` and `Toolbox.getWidth`. (Sessions 6, 9, 25)
- 12: the "Back to Home" button is removed. (Session 8)
- 13: dragging a category box to re-order the menu (upstream addon `toolbox-category-drag`). The held box slides and the others make room. The first and last places are reachable. The order is stored in the project's Stage comment, updated on every change, and reset for projects that have no stored order. (Sessions 10–11)
- 14: the "See Project Page" and "Upload" buttons are removed from the menu bar (sharing-site buttons; this build is for packaged projects). (Session 14)
- 15: no Change Username / cloud variables, Remix, About, Discord links, Help Manual button or analytics script; no cloud server address. (Session 15)
- 16: the original sprite, costume, backdrop and sound libraries are removed. The library windows are `src/components/pm-asset-browser/pm-asset-browser.jsx` (GUI fork); sources in `src/lib/pm-asset-sources.js` (only CC0 / public domain / CC BY / MIT-style licences; never NC, ND, SA, GPL; no brand-logo icon sets). "Surprise" adds a random Kenney item. Every added asset carries a `pmCredit` record, saved in the project by a patch to the VM's `sb3.js`. `pm-credits.js` keeps the "credit" sprite. (Session 17) Clicking a game-icons.net or Iconify icon opens the icon studio (`pm-icon-studio.jsx`, `pm-icon-svg.js`); game-icons tags and author names come from `pm-game-icons-meta.json`. (Session 18) Each library opens on "All", which searches every unlocked source at once (Session 21). Sound waveforms are coloured like Freesound's and made in a background worker, only for tiles in view (Session 21). Openverse / Pixabay show a limit counter; sound tiles play on click and add with "+" (Session 22). Credit lines are as short as the licences allow, licence links listed once at the bottom; the hidden credit sprite holds them in its variable `credit` with a click-to-play credits screen script (also in the backpack), and "Package project" warns when nothing shows that sprite (Session 23).

- 39 (VM + Render): sensing cache when many clones ask. Render: each drawable keeps its touching bounds and CPU preparation (matrix, silhouette) until it moves, turns, resizes, changes costume, shape-changing effect (fisheye, whirl, pixelate, mosaic, ...) or visibility, its silhouette changes, or the next `draw()` (`Drawable._touchingCacheEpoch`, `RenderWebGL._getTouchingCandidateBounds`; pen, text and other skins are prepared every time as before); a candidate list of 8+ asked about again with nothing changed since (no drawable changed, created, removed or reordered, no silhouette updated, same frame) reuses its drawables and bounds (`_cachedCandidatesTouching`, used by `isTouchingDrawables` only). VM: `Sprite.getTouchingCandidates` keeps the "clones not being dragged" list until a clone is created or removed, gets its drawable or starts/stops being dragged (`RenderedTarget.dragging` is a getter/setter); `getSpriteTargetByName` only tries JSON for names starting with "{" (it threw and caught an error per call). Answers identical to the uncached build (`verify.mjs`, 105,000 answers). (Session 39)
- 40 (Render): the section 39 touching cache steps aside when an extension has replaced a Drawable method it relies on (bounds, transform, `update*`, dirty flags; list in `touchingCacheOriginals`) or the renderer's touching helpers: touching then runs exactly as before section 39 (`_touchingCacheUsable`, checked per query). The touching table also does the full check when a drawable's skin was swapped without the setter. Found with SharkPool Camera (precision mode writes drawable fields directly) and Looks Expanded (warp changes bounds silently): 311 of 18,757 answers differed before, 0 after. (Session 40)
- 41 (VM): `Runtime.setInterpolation` is an empty function (`src/engine/runtime.js`), like `vm.setInterpolation` since section 21. SharkPool Camera (TurboWarp and SharkPool galleries) calls `runtime.setInterpolation(false)` while loading; without it the extension threw and any project using it stayed on the loading screen forever. (Session 41)
- 42 (Render + SharkPool and TurboWarp galleries): the touching cache works with SharkPool Camera. Render: `Drawable._calculateTransform` clears the drawable's cache entry (Camera calls it directly); `Drawable._touchingVersion` counts touching-data changes; the safety check no longer watches `updatePosition`, `updateDirection`, `updateScale`, `updateVisible`. Camera (`extensions/SharkPool/Camera.js`, `extension-code/Camera.js`, the same file): precision mode no longer moves drawables back and forth for each check; each camera-bound drawable in a precise check gets a hidden shadow drawable (in `_allDrawables`, not in the draw list) kept at its un-cameraed position, direction, size, stretch, effects, outline, costume and visibility, updated only when the drawable changed; shadows follow costume changes and are removed with their drawable. (Session 42)
