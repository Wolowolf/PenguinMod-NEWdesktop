# EXTENSION-RISKS.md — which extensions a change could disturb

Used by the CLAUDE.md "Extensions" rule: Grep the area (heading) or the extension's name, then decide whether to test. A name here means the extension's code reaches into that part of the engine, and how; it does not mean it will break. Galleries: `pm` PenguinMod, `tw` TurboWarp, `sp` SharkPool; built-in: `vm`. Names are file names (pm/tw: path without `.js`, sp: file name, vm: extension ID).

**How this was made (Session 62, 2026-10-10), only extensions still present (205):** vm 41 = every extension registered in the VM's `extension-manager.js` (28 in the extension library, 13 only load from a project that uses them or as another extension's dependency: `twFiles`, `jgWebsiteRequests`, `jgJavascript`, `jwPostLit`, `jwReflex`, `blockly2math`, `jwXml`, `jwPsychic`, `jwStorage`, `jwDate`, `profanityAPI`, `lmsutilsblocks`, `xeltallivclipblend`); pm 48 = the 45 in `src/lib/extensions.js` + 3 the extension library lists from the PenguinMod gallery folder (`SharkPool/Sound-Waves`, `SharkPool/Tile-Grids`, `DogeisCut/dogeiscutObject`); tw 70 = `extensions/extensions.json`; sp 46 = `Gallery Files/Extension-Keys.json` without `Example` and deprecated ones (what the Extensions tab lists, `galleries.js`). A script (`C:\Users\elias\Documents\PenguinMod-test\scan-extensions.mjs <out.txt>`, uses the local test's checkouts) printed for each one the lines that touch engine internals (replaced functions, runtime events, frame loop, renderer, stage size, touching, compiler, threads, variables, sound, input, clones); those lines were read, and the heavy ones (renderer, frame loop, compiler, scheduler, sensing) checked in the code. Bundled libraries inside an extension (maths.js in `pmOperatorsExpansion`, Box2D, ODE, GIF, MIDI, QR, Pizzicato) were not read. Redo after moving to newer upstream or adding/removing extensions.

## Already overridden by this app (facts, not risks)
- Section 21 forces `maxClones: Infinity`, `miscLimits: false`, `fencing: false`, `dangerousOptimizations: true` (`PM_ALWAYS_ON` in the VM's `runtime.js`, re-applied on every `setRuntimeOptions`) and high quality pen (`setUseHighQualityRender` ignores its argument). So these blocks set nothing: tw `runtime-options` (clone limit, fencing, misc limits, high quality pen), vm `jgRuntime` (`set max clones`, offscreen sprites, misc limits), sp `Scenes` (restores fencing / misc limits), vm `pmCamera` (switches fencing off at load). They still read back the forced values. `disableOffscreenRendering`, `disableDirectionClamping`, warp timer, turbo mode and frame rate still change.
- Interpolation is gone (`vm.setInterpolation` and `runtime.setInterpolation` are empty, sections 21 and 41): tw `runtime-options`' interpolation switch and sp `Scenes` do nothing there; sp `Particle-Engine` and `Runtime-Events` (and `Scenes`) read `runtime.interpolationEnabled`, which stays off.
- vm `pmMotionExpansion` calls the renderer's `getFencedPositionOfDrawable` itself, so its own fencing still works (reasoned, not run).

## No extension at risk
Strong GPU · higher memory limit · Wasm for a few slow parts · heavy jobs in workers · GPU calculations · tilemaps, GPU particles, physics engine, 3D, saving, multiplayer, text scripting, performance hints (new features; only clash if they copy an extension's block names or extension ID).

## Collision and sensing

- Sections 39–42 cache: no present extension replaces a function on its safety list (`touchingCacheOriginals` in Render's `RenderWebGL.js`), so the cache stays on with all of them.
